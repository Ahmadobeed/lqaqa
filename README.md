# القعقاع — ملفات الإصلاح

## الملفات
| الملف | وين يروح |
|---|---|
| `index.html` | الموقع (نفس الملف القديم + إصلاحات فقط) |
| `sw.js`, `notify.wav`, `version.json`, `_headers` | **جنب** index.html بنفس المجلد (جذر الموقع) |
| `worker.js`, `wrangler.toml`, `gen-vapid.mjs` | Cloudflare Worker (يحل محل tg-proxy-worker.js) |

## خطوات التشغيل (بالترتيب)
1. **المفاتيح**: `node gen-vapid.mjs` → الصق `VAPID_PUBLIC` في wrangler.toml، واحفظ `VAPID_PRIVATE_JWK` كسر.
2. عدّل `ADMIN_USERS` في wrangler.toml = يوزرنيم حسابك بالموقع.
3. **الأسرار**:
   ```
   wrangler secret put BOT_TOKEN          # توكن البوت
   wrangler secret put WEBHOOK_SECRET     # أي كلمة سرية طويلة
   wrangler secret put TURSO_TOKEN        # توكن Turso (يفضّل جديد، شوف التحذير تحت)
   wrangler secret put VAPID_PRIVATE_JWK  # من الخطوة 1
   wrangler secret put ADMIN_KEY          # كلمة لتنظيف المكرر
   wrangler deploy
   ```
4. **ربط البوت** (البوت لازم يكون أدمن بالقناتين):
   ```
   curl "https://api.telegram.org/bot<TOKEN>/setWebhook" \
     -d "url=https://al-qaqa.al-qaqa.workers.dev/tg" \
     -d "secret_token=<WEBHOOK_SECRET>" \
     -d 'allowed_updates=["channel_post","edited_channel_post"]'
   ```
5. ارفع index.html + sw.js + notify.wav + version.json + _headers.
6. **تنظيف المكرر القديم** (مرة وحدة): افتح بالمتصفح
   `https://al-qaqa.al-qaqa.workers.dev/dedupe?key=<ADMIN_KEY>` (معاينة) ثم أضف `&apply=1` للتطبيق.
7. عند أي تحديث جاي للموقع: غيّر رقم `BUILD` داخل index.html (سطر `var WORKER=…BUILD=…`) و`version.json` لنفس القيمة — هيك كل الأجهزة تتحدث تلقائياً مرة وحدة.

## تشخيص كل مشكلة (من الكود الفعلي)
1. **الرسائل ما توصل**: `SITE_API=''` فكان `supSend` يخزن بـ localStorage جهاز المستخدم فقط ويرجع (`if(!SITE_API)return`). الآن تُكتب بقاعدة البيانات (جدول `support`) وتصل للّوحة خلال ≈3 ثواني، والرد يرجع للمستخدم.
2. **كاش قديم**: الملف ما فيه Service Worker، فالمصدر هو كاش المتصفح/الاستضافة للـ index.html. الحل: `_headers` (no-cache) + `sw.js` (الشبكة أولاً + يمسح أي كاش/SW قديم) + فحص `version.json` يعيد تحميل مرة وحدة فقط.
3. **الفيديو/الصوت ما يوصل**: ما في أي كود Webhook للبوت بالملف، والاستيراد التلقائي كان معطل (`AUTO_IMPORT=false`) ويعتمد على بروكسيات عامة. الآن Webhook بالـ Worker يحفظ فوراً، والتشغيل عبر `/m/<id>` كمشغّل `<video>/<audio>` نظيف بدون iframe تلجرام.
4. **التكرار**: الأرجح (ما شفت كود البوت القديم) أن تلجرام يعيد إرسال الـ update 2-3 مرات لما الـ webhook يتأخر بالرد، وكل إعادة كانت تنشئ مستند جديد. الآن: رد فوري + معرّف ثابت من `chat/message_id` + فحص `file_unique_id` + منع الإدراج المزدوج بالقاعدة نفسها، وفوقها فلترة بالموقع.
5. **الأزرار المعلقة**: عندك طبقة `body.ssblur{pointer-events:none}` تُفعَّل عند إخفاء الصفحة، ولو علقت تبلع كل اللمسات. صارت لا تمنع اللمس وتنزاح تلقائياً. وطلبات الشبكة صار لها مهلة (كانت تعلق بلا نهاية وتجمّد المستمعين).
6. **توثيق بطيء/بطء عام**: المراقبة كانت كل 15 ثانية وكل مراقب بطلب منفصل (واستعلام `sum(length(data))` يمسح كل الصفوف)، وأي طلب معلّق يوقف المراقب نهائياً. الآن 3 ثواني، كل الطلبات بطلب واحد، فهرس على (col, upd)، وتحديث فوري عند العودة للتطبيق، وإشعار الـ Push عند التوثيق.
7. **الإشعارات**: صوت داخل الموقع (`notify.wav`) + Push حتى لو مسكّر (رسالة جديدة للإدارة، رد الدعم، توثيق، فيديو/صوت جديد).

## حدود لازم تعرفها
- **صوت الإشعار والموقع مسكّر**: المتصفحات تمنع تشغيل ملف صوت من الخلفية. الإشعار يظهر بصوت النظام الافتراضي؛ ملف `notify.wav` يشتغل لما الموقع مفتوح.
- **iPhone**: الـ Push يشتغل فقط إذا الموقع مضاف للشاشة الرئيسية (iOS 16.4+).
- **ملفات كبيرة**: التشغيل يمر عبر صفحة التضمين العامة للقناة؛ إن لم تتوفر يُستخدم `getFile` وحده الأقصى 20MB (قيد تلجرام على البوتات). القنوات لازم تكون عامة.
- **أمان (مهم)**: توكن Turso (قراءة+كتابة) مكتوب داخل index.html ويقدر أي شخص يشوفه ويقرأ/يحذف كل البيانات. هذا موجود من قبل وما غيرته لأنك طلبت إصلاح فقط، لكن يفضّل تدوير التوكن ونقل الوصول عبر الـ Worker لاحقاً.
- ما قدرت أجرّب على تلجرام/Turso/متصفحات حقيقية؛ اختبرت منطق الـ Worker والمزامنة بمحاكاة (قاعدة SQLite حقيقية). جرّب أول مرة بقناة تجريبية.
